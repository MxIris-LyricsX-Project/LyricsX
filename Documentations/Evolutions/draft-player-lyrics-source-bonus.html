摘要

歌曲在 QQ 音乐、网易云音乐、酷狗音乐或「音乐」App 里播放时，来自同一家歌词源（QQMusic、NetEase、Kugou、Apple Music）的搜索结果在匹配分数上加 0.10。加分进入 effectiveQuality，所以自动挑选屏幕上的歌词和搜索面板的排序同时生效，搜索面板的「评分」列照封面加分的写法把加分摊开（1.09 (+0.10)）。

判断「这条歌词是不是播放器自家的」在歌词到达时做一次，结果记进歌词的 metadata；从 bundle ID 认出歌词源的规则是 LyricsXFoundation 里的纯函数，带单元测试。「设置 → 歌词源」页加一个默认勾选的开关，「按歌词源顺序优先」模式下这个开关不起作用，显示为不可用。

PlayerLyricsSourcePolicy.swift 
extension LyricsProviders.ServiceID {
    public init?(playerBundleIdentifier bundleIdentifier: String) {
        let components = bundleIdentifier.lowercased().split(separator: ".")
        guard components.count >= 3, components[0] == "com" else { return nil }
        switch (components[1], components[2]) {
        case ("tencent", let product) where product.hasPrefix("qqmusic"):
            self = .qq
        case ("netease", "163music"), ("netease", "cloudmusic"):
            self = .netease
        case ("kugou", _):
            self = .kugou
        case ("apple", "music") where components.count == 3:
            self = .appleMusic
        default:
            return nil
        }
    }
}

public enum PlayerLyricsSourcePolicy {
    public static let matchBonus = 0.1

    public static func lyricsService(
        _ service: String?,
        belongsToPlayerWithBundleIdentifier playerBundleIdentifier: String?
    ) -> Bool {
        guard let service, let playerBundleIdentifier,
              let playerSource = LyricsProviders.ServiceID(playerBundleIdentifier: playerBundleIdentifier) else {
            return false
        }
        return playerSource.displayName == service
    }
}
  • 按点分段匹配而不是子串：子串会把名字里碰巧带这几个字母的别家 App 也算进来。
  • com.apple.music 要求正好三段，扩展、插件不算。
App 侧：Global.swift 
static let playerLyricsSourceBoostEnabled = Key<Bool>("PlayerLyricsSourceBoostEnabled")

private let isFromPlayerLyricsSourceKey = Lyrics.Metadata.Key("LyricsX.IsFromPlayerLyricsSource")

extension Lyrics {
    var isFromPlayerLyricsSource: Bool {
        (metadata.data[isFromPlayerLyricsSourceKey] as? Bool) ?? false
    }

    func markPlayerLyricsSource(playerBundleIdentifier: String?) {
        metadata.data[isFromPlayerLyricsSourceKey] = PlayerLyricsSourcePolicy.lyricsService(
            metadata.service,
            belongsToPlayerWithBundleIdentifier: playerBundleIdentifier
        )
    }
}

func effectiveQuality(_ lyrics: Lyrics) -> Double {
    let quality = lyrics.quality.isFinite ? lyrics.quality : 0
    return quality + effectiveArtworkBonus(lyrics) + effectivePlayerLyricsSourceBonus(lyrics)
}

func effectivePlayerLyricsSourceBonus(_ lyrics: Lyrics) -> Double {
    guard defaults[.playerLyricsSourceBoostEnabled], lyrics.isFromPlayerLyricsSource else { return 0 }
    return PlayerLyricsSourcePolicy.matchBonus
}
  • 存「是不是」，不存加分值：值由策略给出，以后调整 0.10 不必考虑已经打过标记的歌词。
  • 到达时打标记、不在比较时现算：比较函数在候选池的有序插入里反复调用，播放器中途换了的话，现算会让同一个池子前后用两套比较规则，插入位置就不可信了。到达时的过滤（请求 id、currentTrack）保证读到的是这首歌所在的播放器。
  • 写 metadata 不切到 lyricsDisplay 队列：两处都在歌词进候选池或面板列表之前写，这时还没有读者，与 cacheQualityBeforeDisplay() 同一个时机。
  • 面板手动搜别的歌时也按当前播放器打标记：同一来源统一加分，不会把错歌顶上来。

private func playerBundleIdentifier(of player: MusicPlayerProtocol?) -> String? {
    switch player {
    case let agent as MusicPlayers.Agent:
        return playerBundleIdentifier(of: agent.designatedPlayer)
    case let scriptable as MusicPlayers.Scriptable:
        return scriptable.playerBundleID
    case let systemMedia as MusicPlayers.SystemMedia:
        return systemMedia.playerBundleID
    default:
        return nil
    }
}

动机与调研

动机
  • 在 QQ 音乐里播放薛之谦的《一半》，搜索面板排第一的是 Kugou 的 1.05，QQMusic 的同一首歌只有 0.99。两条都是对的歌，差的 0.06 来自 LyricsKit 给翻译和逐字时间各加的 0.05，而不是匹配程度。QQ 音乐自家的歌词按它曲库里这一版录音做时间轴，别家的同名歌词可能来自另一个版本。
  • 0003 的排序模式和拖动排序是一张固定的全局列表，用户在 QQ 音乐和网易云之间切换播放器时只能每次去设置里拖。
  • Lyrics.quality 只看歌手、歌名、时长和两项特性；App 侧唯一的附加项是封面相似度加分。
前期调研
  • 分数：Lyrics.quality（Lyrics+Quality.swift:43）= 歌手 0.45 + 歌名 0.40 + 时长 0.15，夹到 [0, 1]，再加翻译 +0.05、行内时间标签 +0.05，伴奏版 −0.3。App 侧 effectiveQuality(_:)（Global.swift:380）= quality + 封面加分，候选池和搜索面板都经 lyricsHasHigherPriority 用它比较；面板评分列（SearchLyricsViewController.swift:533）显示同一个数。
  • 封面加分是先例：值存在 metadata.data（LyricsX.ArtworkMatchBonus），开关在 effectiveArtworkBonus 里判断。它异步算出，要在 lyricsDisplay 队列写、写完重排；本提案的判断是同步的，进候选池之前就写完。
  • 到达入口：AppController.lyricsReceived（:1211，MainActor，含「下一条候选」补搜）先按请求 id 和 currentTrack 过滤，再 cacheQualityBeforeDisplay()，然后才进候选池；面板的 lyricsReceived（:455）也在 MainActor。
  • 歌词源名字：provider 把 static let service 写进 metadata.service："QQMusic"、"NetEase"、"Kugou"、"Apple Music" 等，与 ServiceID.displayName 逐字相同。
  • 当前播放器的 bundle ID：PlaybackRouteLyricsOffsetController.playerBundleIdentifier(of:)（:131-145）穿过 Agent 取 Scriptable.playerBundleID 或 SystemMedia.playerBundleID，在主队列上读。
  • bundle ID（本机核对）：com.tencent.QQMusicMac、com.netease.163music；允许列表里还有 iPad 版 QQ 音乐 com.tencent.QQMusic.D5Q73692VW；「音乐」是 com.apple.Music。推测，未核对：酷狗本机没装，iOS 版是 com.kugou.kugou1002，Mac 版应同样以 com.kugou. 开头；网易云 iOS 版 com.netease.cloudmusic。
  • 不会加分的歌词：歌词库 .lrcx、内嵌歌词、旁边的 .lrc 都没有 metadata.service。
  • 翻译副本带标记：AI 翻译结果整份复制 metadata（AILyricsTranslation.swift:409）。
  • 三种排序模式：「只按匹配分数」严格大于才更优；「同分再看源」按 0.02 分桶，0.10 是五个桶；「按歌词源顺序优先」先比来源位置，同一来源的结果全都加或全都不加，加分改变不了顺序。
  • 0.10：截图里 0.99 + 0.10 = 1.09 > 1.05；对方两项特性都有、自家一项没有时打平，留给先到的那条；歌名或歌手对不上的结果落后 0.3 以上，翻不了盘。封面加分 0.15，两项可以叠加。
非目标
  • Spotify 不对应 Musixmatch：Spotify 的歌词由 Musixmatch 提供，但不是 LyricsX 搜到的那一份。
  • 不给本地歌词加分：它们不知道来源。
  • 切换开关不重排已有候选，下一次搜索或面板下一次重排时生效。
  • 加分值不做成设置项。
  • 不改 LyricsKit。
  • 不改「按歌词源顺序优先」模式的语义，不自动调整来源列表。

替代方案

8 条，全部否决
  • 比较时现算：播放器中途变化会让候选池前后用两套比较规则，有序插入失效。
  • 放进 LyricsKit 的 quality：LyricsKit 不知道播放器，要改请求、发版本；quality 还会被缓存，开关切换后清不掉。
  • 按播放器自动调整来源列表：改写用户自己排的顺序，默认模式下也无效。
  • 加分取 0.15：自家一项特性都没有也能稳赢翻译加逐字的版本；0.10 让这种情况打平。
  • 子串匹配 bundle ID：会误伤别家 App。
  • 放进实验室页：这是关于歌词源的偏好，放在歌词源页用户调来源时一眼能看到。
  • 不做开关：有的用户更看重翻译或逐字歌词；用户选了加开关。
  • 只在搜索面板加分：面板显示的分数就和实际排序不一致了；用户选了两处都加。

影响

  • 用户可见：在 QQ 音乐、网易云音乐、酷狗音乐或「音乐」里播放时，自动挑选更常选到它自家的歌词，面板里它们排得更靠前、评分列带 (+0.10)；歌词源页底部多一个默认勾选的复选框和一行说明，「按歌词源顺序优先」时变灰；其他播放器行为不变。
  • 可发现性：默认开启，用户不需要知道它存在就能受益；评分列的 (+0.10) 说明某一行为什么高。
  • 数据与配置：新键 PlayerLyricsSourceBoostEnabled 注册默认 true，不需要迁移；新的 metadata 键只在内存里，不写进歌词库；降级后不加分，升级回来设置仍在。
  • 平台：无变化，部署目标仍是 macOS 12。
  • 发布：不需要新权限、entitlement 或隐私清单条目，不影响公证与 Sparkle；下一版发布说明加一条。
