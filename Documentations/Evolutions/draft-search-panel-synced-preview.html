摘要

「搜索歌词」面板底部不再显示选中结果的 LRC 原文，而是换成浮动歌词窗口用的那种滚动歌词视图（ScrollLyricsView）：选中一条结果，就按它的时间轴显示歌词，正在唱的那一行高亮并保持在中间，跟着播放器的进度往下走。时间按「播放器位置 + 这条歌词应用之后会用的总偏移」计算，所以预览里看到的进度就是点「应用」之后屏幕上会看到的进度；双击某一行跳到那里播放，方便对一下时间轴。结果不属于正在播放的歌时，预览只显示歌词、不标进度。

面板开着的时候，播放器换了歌，标题和歌手两个输入框就换成新歌的名字并重新搜索；面板关着时不做任何事，下次打开时照旧按正在播放的歌刷新。判断「要不要重搜」和「预览要不要跟进度」是 LyricsSearchPanelResults 上的两个纯方法，有单元测试。

没问就定下的

  • 预览复用浮动窗口的逐行滚动视图，不嵌 Apple Music 引擎的逐字扫光（理由见替代方案）。
  • 切歌时直接换掉输入框与结果，用户改过的搜索词也换；播放器退出时保留结果。
  • 不自动选中结果；没选中时显示一行占位文字。

提议方案

一、底部换成跟着播放走的预览

  1. storyboard 里把原文视图换成 ScrollLyricsView + LyricsTextView；约束、最小高度和「收起 → 首次选中时展开」不变。
  2. 外观：系统字体 13 pt，普通行 secondaryLabelColor，当前行 controlAccentColor。
  3. 选中一条结果就装入它、恢复自动滚动、立即刷新一次进度；没选中时清空并显示占位文字。
  4. 刷新进度：只在结果属于正在播放的歌时标行；位置 = lyricsDisplayTime(trackDuration:) + adjustedTimeDelay；正在播放就在下一行开始时再刷新，过了最后一行每秒复查。触发：选中变化、播放状态变化、全局偏移与设备偏移变化、定时器。
  5. 交互：手动滚动停止自动滚动；双击某行（跟随时）跳播并恢复自动滚动；没有右键菜单。

二、搜索框跟着正在播放的歌切换

  1. 窗口出现时订阅 currentTrackWillChange.removeDuplicates().receive(on: main)，消失时取消、停掉预览定时器。
  2. 换了一首歌时结束输入框编辑、填入新歌的标题和歌手（不读恢复名）、为它搜索；曲目变成 nil 时保留结果。
  3. searchAction(_:) 转调新的 search(for:)，切歌那条路传入发布出来的曲目。
  4. 打开面板照旧刷新，另补「曲目 id 变了也重搜」。

非目标

  • 不在预览里调偏移；不做逐字卡拉OK进度，不嵌 Apple Music 引擎。
  • 不自动选中第一条结果；面板关着时不跟着切歌。
  • 恢复名晚到时不改输入框、不重搜；不改「应用」的语义。
  • 不再在面板里显示 LRC 原文；要原文的把结果行拖出去即可（已有功能）。

详细设计

LyricsSearchPanelResults 的两个新方法 
extension LyricsSearchPanelResults {
    /// Whether a new search should replace these results now that
    /// `currentTrackIdentifier` plays: another track has started. With
    /// nothing playing the results stay.
    public func needsNewSearch(whilePlaying currentTrackIdentifier: String?) -> Bool {
        guard let currentTrackIdentifier else { return false }
        return currentTrackIdentifier != trackIdentifier
    }

    /// Whether the preview of the selected result marks the line at the
    /// playback position: only while the track the results were found for plays.
    public func previewFollowsPlayback(whilePlaying currentTrackIdentifier: String?) -> Bool {
        guard let trackIdentifier else { return false }
        return trackIdentifier == currentTrackIdentifier
    }
}

两者故意不对称：没在播放时手动搜的结果（trackIdentifier == nil）遇到新歌开始播放要重搜，但它的预览永远不跟进度。命名与已有的 application(whilePlaying:) 同形。

进度刷新 refreshPreviewProgress(animated:) 
private func refreshPreviewProgress(animated: Bool) {
    previewLineCheck?.cancel()
    previewLineCheck = nil
    guard let lyrics = panelResults.selectedResult,
          panelResults.previewFollowsPlayback(whilePlaying: selectedPlayer.currentTrack?.id) else { return }
    let playbackState = selectedPlayer.playbackState
    let playbackTime = playbackState.lyricsDisplayTime(trackDuration: selectedPlayer.currentTrack?.duration)
    let position = playbackTime + lyrics.adjustedTimeDelay
    lyricsPreviewView.highlight(position: position)
    if isPreviewTracking { scrollPreview(to: position, animated: animated) }
    guard playbackState.isPlaying else { return }
    let delay: TimeInterval
    if let nextLineIndex = lyrics[position].nextLineIndex {
        delay = max(0, lyrics.lines[nextLineIndex].position - position)
    } else {
        delay = 1
    }
    let queue = DispatchQueue.main
    previewLineCheck = queue.schedule(after: queue.now.advanced(by: .seconds(delay)),
                                      interval: .seconds(42), tolerance: .milliseconds(20)) { [weak self] in
        self?.refreshPreviewProgress(animated: true)
    }
}

定时器写法照 AppController.scheduleCurrentLineCheck：可取消的重复调度当一次性定时器用，每次刷新先取消上一个。

切歌订阅与窗口可见性

viewWillAppear 里订阅 currentTrackWillChange（去重、切主线程）、playbackStateWillChange、全局偏移与设备偏移；viewDidDisappear 清空订阅集合并取消预览定时器。playbackStateWillChange 同样在 willSet 里发出，receive(on: main) 是异步投递，读到时属性应已更新；实现时以实际行为为准，读到旧值就改用发布出来的 PlaybackState。

调研

现状与依据
  • 原文看不出时间轴：底部显示 Lyrics.description（SearchLyricsViewController.swift:289），要自己拿时间标签加上三层偏移心算。
  • 「先应用再看」会留痕：apply(_:to:) 会标亲选、写库、记覆盖表、交候选池、可能写进 Music。
  • 输入框只在打开时更新：viewWillAppear 与 showWindow 才调 reloadKeyword()；面板控制器由 AppDelegate.searchLyricsWC 常驻，订阅必须跟着窗口可见性。
  • 现成的视图：ScrollLyricsView 已有按时间高亮、滚到中间、双击回调、滚轮回调、边缘渐隐；默认颜色是浮动窗口深色背景用的，要换成系统颜色。
  • 进度算法：照 AppController.scheduleCurrentLineCheck——lyricsDisplayTime + adjustedTimeDelay，lyrics[position] 找当前行与下一行，在下一行开始时再算。
  • 偏移与应用后一致：adjustedTimeDelay = 歌词 offset + 全局偏移 + 设备偏移，只依赖歌词本身和全局状态。
  • 切歌发布者先于属性更新：Scriptable 的 currentTrackWillChange 就是 $currentTrack，在 willSet 里发出；现在的 searchAction 读 selectedPlayer.currentTrack，同步调用会搜成上一首。
  • 恢复名的竞争：currentLyrics 在歌词队列上清空，面板在主线程处理切歌时它可能还是上一首的，读它的 searchPluginTerm 会填错名字。
  • 「存给原来那首歌」仍然需要：曲目变 nil 时与切歌瞬间仍靠它（b2262cd1 引入）。

替代方案

7 条，均已否决
  • 嵌 Apple Music 引擎看逐字扫光：为深色大窗口设计，有 display link 与 Metal 背景，HostEnvironment 是全局单例；逐行高亮已能回答「对不对得上」。
  • 只显示一行卡拉OK：看不出前后整体是否偏了一段。
  • 保留原文并加切换：需求是不再显示原文；原文能靠拖出结果行拿到。
  • 固定频率刷新：面板开着时一直唤醒主线程；按行边界排定时器是现成做法。
  • 面板关着也跟着切歌：没人看，后台搜索只浪费请求。
  • 改过输入框就不跟：为上一首改的搜索词对新歌没有意义。
  • 恢复名晚到时重搜：会把用户正在看的列表整个换掉；面板自己的搜索也走恢复名插件。

影响

  • 用户可见：底部原文换成跟着播放滚动的歌词；双击一行跳播；面板开着时换歌，输入框和结果跟着换（还没应用的上一首结果会被换掉）；原文仍可拖出结果行拿到。
  • 可发现性：无新设置；预览在首次选中结果时随窗口展开出现，占位文字说明用途。
  • 数据与配置：不新增、不改动任何偏好、歌词文件或缓存。
  • 平台：不变（macOS 12+）。
  • 发布：不涉及权限、公证或 Sparkle；下次发布说明写这两处变化。

落地步骤

  1. 两条判断与测试：aNewTrackStartingNeedsANewSearch、theSameTrackPlayingOnNeedsNoNewSearch、nothingPlayingKeepsTheResults、aTrackStartingAfterASearchTypedWithNothingPlayingNeedsANewSearch、thePreviewFollowsPlaybackWhileTheSearchedTrackPlays、thePreviewStopsFollowingOnceAnotherTrackPlays、thePreviewOfASearchTypedWithNothingPlayingNeverFollowsPlayback。
  2. 底部换成跟着播放走的预览：选中即显示并高亮当前行；到点换行；暂停停住、拖动跳行；偏移变化随之移动；手动滚动停止自动滚动、双击跳播恢复；不属于当前歌时只显示；占位文字；深浅外观；拖出仍是原文。
  3. 输入框跟着切歌：开着时换歌重填重搜；只换封面不重搜；播放器退出保留结果；正在输入时换歌显示新名字；关着不搜、再打开刷新；同名另一首也重搜。
  4. 文档与收尾：候选池实现说明第五节、项目 CLAUDE.md 测试清单。

步骤 1 跑 swift test --filter LyricsSearchPanelResultsTests；步骤 2、3 构建整个 app，界面行为由用户手工检查，agent 不自行操作界面。预计不需要单独的实现说明，也没有新术语，落地时再确认。
