摘要

「设置 → 歌词源」页的歌词源表里，每个歌词源名字前加一个复选框，默认全部勾选。取消勾选的歌词源不再参与任何联网搜索——换歌时的自动搜索、手动搜索面板、「下一条候选」快捷键都不会再向它发请求，也就不会再出现它的歌词。

设置存成一个「被关掉的歌词源」列表（DisabledLyricsSources，存 LyricsProviders.ServiceID 的 rawValue），空列表即全开，以后 LyricsKit 新增的歌词源默认也是开的。判断逻辑是 LyricsXFoundation 里的纯值类型 LyricsSourceSwitches，有单元测试；AppController.updateLyricsManager() 只为开着的歌词源创建 provider。

自行决定的事

没有待定问题；以下几点按默认做法定了，可以推翻

  • 手动搜索面板和「下一条候选」也排除关掉的源（三条路径共用同一个 lyricsManager）。
  • 下一次搜索才生效，不重搜当前歌曲，屏幕上的歌词不动。
  • 已保存的歌词不过滤：歌词库文件不记录来源，无从判断。
  • NetEase 高清封面、Apple Music 原名恢复与 token 检查不跟着歌词源开关走。
  • 「只按匹配分数」模式下表不再整体变灰：复选框能点，只是不能拖动、序号淡化。
  • 一个源都不开是合法设置，不加额外提示。

详细设计

LyricsSourceSwitches 
/// Which lyrics sources the user has switched off on the Source pane.
public struct LyricsSourceSwitches: Equatable, Sendable {
    /// What the preference stores, in the order the sources were switched off.
    public private(set) var disabledSourceIdentifiers: [String]

    public init(disabledSourceIdentifiers: [String] = []) {
        var seenIdentifiers = Set<String>()
        self.disabledSourceIdentifiers = disabledSourceIdentifiers.filter { seenIdentifiers.insert($0).inserted }
    }

    public func isEnabled(_ service: LyricsProviders.ServiceID) -> Bool {
        !disabledSourceIdentifiers.contains(service.rawValue)
    }

    public mutating func setEnabled(_ isEnabled: Bool, for service: LyricsProviders.ServiceID) {
        disabledSourceIdentifiers.removeAll { $0 == service.rawValue }
        if !isEnabled {
            disabledSourceIdentifiers.append(service.rawValue)
        }
    }
}
  • 命名照 NSSegmentedControl 的逐项开关：isEnabled(forSegment:) / setEnabled(_:forSegment:)。
  • 存 rawValue 而不是 displayName：显示名是界面文字，改一个字旧设置就对不上。
  • 构造时去重，避免重复值造成「打开一次还关着」。
  • 读不懂的标识符（更新的版本写入的）原样保留，在这里切换别的源不会把它重新打开。

动机与调研

动机：现在只能排序，不能排除
  • updateLyricsManager()（AppController.swift:274）每次都把五个免凭据的歌词源全部装进 LyricsProviders.Group，token 有效时再加 Apple Music。0003 的三种排序模式只决定「谁排前面」，不决定「谁参与」。
  • 默认的「只按匹配分数」模式下，不信任的源只要分数高就会上屏；即使拖到最后，别的源没结果时它仍会上屏，并照样出现在搜索面板与候选池里。
  • 连不上的源每次搜索都白等到超时；质量系统性地差的源只能一首首手动换掉。
调研：LyricsKit 已具备按 ID 挑选的能力，三条搜索路径共用一个入口
  • LyricsProviders.ServiceID 是 String rawValue 的 CaseIterable 枚举：netease、qq、kugou、musixmatch、lrclib、appleMusic；每个 Service 都带 id。不需要发 LyricsKit 新版本。
  • 自动搜索（AppController.swift:583）、「下一条候选」补搜（:1369）、搜索面板（SearchLyricsViewController.swift:17）都读同一个 lyricsManager。
  • Group.lyrics(for:) 在 providers 为空时立即结束，自动搜索随即走「没结果就读歌词库」的现有分支，不会卡住。
  • 歌词库 .lrcx 不记录来源：本机 2891 个文件的元数据标签里没有任何一个记录歌词源，[by:] 是歌词作者字段，不可靠。
  • 「只按匹配分数」模式（默认值）下整张表 isEnabled = false、半透明（PreferenceSourceViewController.swift:63-64），放进复选框后必须改。
  • GenericID 的 Key<[String]> 未注册时读出空数组，新键不需要改 UserDefaults.plist。

替代方案

六条，全部否决
  • 存「开着的」列表：以后新增的源会默认关闭，与「默认全开」相反。
  • 复用 displayName 当标识符：显示名是界面文字，改名即失配。
  • 照常搜索、再丢掉关掉的源的结果：请求照发，连不上的源照样拖慢搜索。
  • 在 LyricsKit 里加「启用的源」参数：挑选在 App 里做就够，改 LyricsKit 要发版、改版本号，收益为零。
  • 在 storyboard 新增一列复选框：表格更挤；画新列要算 frame、改约束，风险更大。
  • 切换后立即重搜当前歌曲：会换掉屏幕上的歌词，用户只是在调设置。

影响

用户可见变化

  • 「设置 → 歌词源」表的「来源」一列变成复选框，默认全部勾选。
  • 「只按匹配分数」模式下表不再整体变灰：复选框可以点，只是不能拖动、序号淡化。
  • 关掉的歌词源不再出现在自动搜索、手动搜索面板和「下一条候选」里。

数据与配置兼容

  • 新键 DisabledLyricsSources，未写入时为空数组即全开，不需要迁移。
  • 降级到旧版本时所有源恢复开启；再升级回来开关设置仍在。
  • 已保存的歌词不受影响。

平台与发布

  • 最低版本不变（macOS 12）；不需要新权限，不影响公证与 Sparkle。
  • 下一版发布说明加一条「歌词源可以单独关掉」。
