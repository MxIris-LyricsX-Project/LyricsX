# 0032 - 记住无法原地写回的歌词偏移

- **状态**: Implemented
- **创建日期**: 2026-11-19
- **最后更新**: 2026-11-20
- **实现分支**: LyricsX `feature/shift-time-by-update-tag`
- **相关提案**: [0029 按播放器与输出设备设置歌词偏移](0029-playback-route-lyrics-offset.md)

## 行为

状态菜单和快捷键调整当前曲目的歌词偏移，单位为毫秒，正值让歌词提前。播放时每行时间戳保持原样，显示时将本曲偏移与全局偏移、播放路由偏移相加。歌词面板和翻译仍可用原来的时间戳识别同一行。

写回其他播放器也会读取的歌词源时，本曲偏移计入每行时间戳，文件不再带 `[offset:]`，因为许多播放器不识别这个标签。逐字时间从行首起算，随行移动。提前的偏移使开头几行早于 0 秒时，这些行放在 `00:00.000`。写回后该来源的偏移为 0：下次载入时状态菜单显示 0，歌词出现的时间与写回前相同。全局偏移和播放路由偏移补偿的是本机的播放延迟，不计入。

| 写入目标 | 偏移写成 |
| --- | --- |
| 歌曲同目录的歌词文件（开启写回） | 每行时间戳 |
| Music 的歌词（「将歌词写入 iTunes 歌曲」、自动写入，以及下文的内嵌歌词写回） | 每行时间戳 |
| LyricsX 歌词库，包括自定义目录 | `[offset:]` 标签。已保存的翻译按行时间戳与来源歌词对应，改动时间戳会使其对应不上 |

| 歌词来源 | 偏移从哪里读回 |
| --- | --- |
| 可原地写回的歌词文件 | 写回后的时间戳或歌词库文件的 `[offset:]` 标签，或尚未写回的匹配记录 |
| Music 的内嵌歌词（开启写回、纯 LRC 写入、本地文件曲目时，切歌后写入 Music） | 写入后的时间戳，或尚未写入 Music 的匹配记录 |
| 内嵌歌词的其他情况、关闭写回时的同目录歌词，以及其他保存目标与来源不同的本地歌词 | LyricsX 的 `TrackLyricsOffsets`。没有匹配记录时使用来源原有的 `[offset:]` |

## 存储

`TrackLyricsOffsets` 存在 UserDefaults 中，以播放器提供的曲目 ID 为键。每条记录带有歌词指纹，由行时间戳、文字和来源原有的偏移组成。偏移基准在读取时记录，重复选择菜单里的同一份歌词时沿用。歌词或来源偏移有变化后，使用新来源自带的值。匹配的记录可以用 0 覆盖原有的非零偏移。

开启写回后，匹配的记录继续生效，直到 LyricsX 成功把偏移写入原来源，届时删除这条记录。保存失败或只写到歌词库副本时，记录仍然保留。清理长期未用的记录和恢复来源偏移的设置入口可另行设计。

手动选择或自动载入本地歌词时，LyricsX 按原来源恢复偏移。翻译生成歌词库副本后，当前显示仍以原来源决定偏移存放位置。歌词文件保存仍走现有的目标判断。导入的歌词继续保存为歌词库副本。

内嵌歌词在开启「允许将修改写回正在用的歌词源」、歌词写入 Music 选用纯 LRC、播放器为 Apple Music 且曲目有本地文件时，于切歌后用 `musicLyricsContent` 的结果写入 Music。写入走后台队列，目标是显示歌词时固定住的曲目引用。写入后读回比对，一致才删除匹配记录；不一致时记录保留。该文本由已解析的歌词重新生成：繁简转换和翻译会反映在 Music 中，逐字时间不保留。其他情况下调整偏移不调用写入 Music 的操作。Music 中的时间戳改动后，歌词库副本里按原时间戳保存的翻译会对应不上一次，重新翻译后副本按新时间戳保存。

偏移换算在 LyricsX 内完成（`Lyrics.withOffsetInLineTimes`），不需要 LyricsKit 新增序列化选项。
